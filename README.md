# Ordobit Website

Static website for the Ordobit public homepage and device-client downloads.

## Structure

```
ordobit-website/
├── .github/workflows/
│   └── test-publish.yml              # Refreshes the test release manifest
├── index.html                        # Landing page
├── downloads/
│   └── index.html                    # Platform download cards
├── releases.json                     # Release manifest consumed by downloads page
├── scripts/
│   └── sync-releases.mjs             # Reads public app updater metadata
├── styles.css                        # Global shared styles (tokens, layout, components)
├── assets/
│   ├── ordobit-logo.svg
│   └── icons/
│       ├── windows.svg
│       ├── linux.svg
│       └── android.png
├── components/
│   ├── header.js                     # Reusable site header renderer
│   └── footer.js                     # Reusable site footer renderer
├── pages/
│   ├── landing/
│   │   ├── landing.css               # Landing page-specific styles
│   │   └── landing.js                # Landing page rendering
│   └── downloads/
│       ├── downloads.css             # Downloads page-specific styles
│       └── downloads.js              # Card rendering + shared header/footer
└── shared/
    ├── constants/
    │   └── platforms.js              # Platform definitions & release defaults
    └── utils/
        ├── dateUtils.js              # Date formatting helper
        └── fileUtils.js              # File-size formatting helper
```

## Local preview

Because the downloads page fetches `releases.json`, serve the folder through a
small local HTTP server instead of opening the file directly:

```bash
python3 -m http.server 4173
```

Then open <http://localhost:4173>.

## Touch & Device Support

The site is designed for kiosk and touch devices:

- **48 px minimum tap targets** on all interactive elements (buttons, nav links)
- **`touch-action: manipulation`** on `body` to prevent double-tap zoom
- **`-webkit-tap-highlight-color: transparent`** for cleaner touch feedback
- **`@media (pointer: coarse)`** overrides that enlarge controls to 52 px on touch devices
- **`user-scalable=no`** viewport for kiosk lockdown mode

## Publishing latest builds

The **Test Publish** workflow fetches the public updater metadata generated by
the device-client release process:

```text
windows/latest.yml
linux/latest-linux.yml
android/latest-android.json
```

Those files provide the latest version, installer filename and file size. The
workflow converts them into `releases.json`, commits the result to the `test`
branch and lets Vercel deploy that branch.

Create a GitHub environment named `test` with one variable:

```text
DOWNLOADS_BASE_URL=https://downloads.example.com
```

Run **Test Publish** manually after the device-client test release completes.
The metadata URLs must be publicly readable. A missing platform metadata file
keeps its existing entry unchanged.

## Hosting

The repository contains only static website files. Vercel deploys the `test`
branch after the workflow pushes the refreshed manifest. Production remains
unchanged until the reviewed test changes are merged into its branch.
